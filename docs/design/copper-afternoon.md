# Copper Afternoon

Status: concept for Astra wildcard review. No game built. Based on the second approved concept: an original direct-manipulation repair bench, with its own drawings, object layouts and level sequence. Canvas 2D, TypeScript, current monorepo HF and published lab client. Compare against Small Works before building: this game's purpose is tactile inspection and object change, not another dialogue menu for workshop assignments.

## What the player does

Repair a wind-up desk lamp, a hand bell and a toy cart through an afternoon. These are deliberately fictional low-voltage/mechanical objects, not electrical repair instructions. Rotate each object, expose a fault, choose a part, fit it and test it. Three objects and two waiting visitors form the whole run, about six minutes. Parts are scarce; a rushed test can damage a part. Missed work and honest return of an unrepaired object are real endings. A successful physical fix does not erase a broken promise.

The bench fills most of the screen. Warm ochre cutaways, large tools, changing gears, a lit bulb and the waiting people's motion show progress. Unfastened screws remain visibly on the bench. A wrong connection leaves a gap or stops the movement. Text is brief object labels and speech, not a list of repair verbs.

## First minute

A cart wheel wobbles on the bench before any text. Its axle cap pulses; touching it opens a cutaway. A visible bent pin can be removed with the nearby pliers. A broad ghost shape shows the replacement pin's destination. Fit it and spin the wheel; it rolls straight across the bench and the owner visibly responds. The real first repair is complete. One prompt at a time attaches to the actual object and waits for action. The tutorial can be skipped or replayed. The next object adds a deadline and a part allocation choice; teaching does not lower the later difficulty.

## Cast and agency

Use canonical Sam, Rafi and Aylin with existing ids, profiles, biographies and restrictions. Sam and Rafi are learners; neither gains electrical certification or automatic mastery from a new role. Aylin owns an object with a practical family reason to need it. Add these role allocations and exact carry mapping to the HF registry before building. No new foreground person or adaptation of another game's characters.

The host owns object geometry, assembly correctness, inventory, opening and closing time. HF owns people's ordinary commitments, learning, fatigue, memory and response to a request. Ask Rafi to hold an axle while doing a different repair; he may agree, decline because he is committed elsewhere, or stop at the agreed time. His actual activity changes the visible bench. The player can finish unaided with a slower clamp. An accepted request never becomes a permanent worker bonus. Revalidate requests when the part or person moves. Before adding the second object, demonstrate one actual accepted/refused request from public HF APIs, a kept/broken promise with a later observable effect and a fixed-response comparison. Report unsupported generic faculties to HF rather than writing parallel person rules.

The player can admit that an attempted repair broke a part. Aylin decides whether to wait or take the object away through a supported public interaction, not a host score threshold. Her ordinary speech and departure reveal the outcome; no private traits or secrets appear on HUD. A second encounter responds to the actual earlier event. A single action does not guarantee forgiveness.

## Input, replay and access

Each drag has a tap-select, tap-destination alternative. Keyboard focus traverses the same large hotspots; Enter selects and arrow keys move between meaningful targets. Pointer precision and timed button mashing are not required. A slow-time setting changes wall time only; menu pauses. Record normalized semantic object actions and accepted timing ticks, not raw pixel coordinates. Fixed seeded simulation; frame motion interpolates, never drives outcomes. Exports pin seed, host edition, exact HF/build, cast admission, initial state, all normalized inputs and final hash. Replay is offline and model-free. Namespaced stores and path-scoped service worker; no old saves imported.

## Astra review resolution — 2026-11-05

The wildcard review conditionally retained the concept. The actual visitor is Aylin, who brings the bell and lamp and returns once before closing; the cart is workshop stock. Sam and Rafi are coworkers, not two additional owners. This is three foreground people and one visitor.

The cart teaches removing a bent axle pin and fitting a straight pin; its unpowered roll test visibly wobbles or rolls straight. The second object is a bell whose removable spacer can sit under the bell or under the striker. Only the striker position leaves enough clearance to ring. The player must infer that from the cutaway and visible silent strike; it has no answer highlight. The third is a wind-up lamp whose asymmetric coupling can face the winding gear or block it. A hand crank test moves the gear; a visibly loose coupling can break if the player chooses to turn the crank before fastening it. Damage follows a visible unsafe configuration, never fast clicking. These fictional objects do not provide electrical instructions.

There is one rigid coupling usable either in the bell's missing striker link or the lamp transmission. Show the same physical silhouette and both vacancies before fitting it. Removing a fastened coupling costs a visible operation and consumes time, so a player can change the plan before the object leaves but cannot repair both while the part is absent. Aylin can take the working bell and leave the lamp, or the reverse, or wait. Her two objects have distinct animated failed tests.

Rafi can hold the axle for 30 simulation seconds after accepting a request. The clamp otherwise holds it for the same physical operation and occupies the bench's only mounting socket. While Rafi holds, the clamp can mount the bell; without him, the player must finish the cart before mounting it. A refusal changes the available sequence, not a percentage speed bonus. At his agreed departure time he releases only after warning and placing the object safely on the bench; a revalidated action can cancel instead of damaging it invisibly.

Sam independently takes the tested item to the visitor only after deciding he has sufficient received test evidence. A request to call an untested object checked may be refused through an ordinary public HF interaction. This is a novice deciding what he can report, not certification. If the public API cannot support that specific action, keep Sam on a bounded ordinary competing commitment that changes which tool he can bring; do not invent a host honesty score. Freeze one supported behavior in the initial HF trace before full content expansion.

Aylin returns at 240 simulation seconds and the bench closes at 360. If she left earlier, her return is a visible authored arrival. Deliver the actual damage/admission/promise event to her when it occurs. The matched memory control uses identical later geometry and request, changing only a genuinely received earlier event. A different finished object alone is not memory evidence. Tick order is semantic input, preconditions, HF decision, scheduled operation completion, deadlines, render snapshot. Menu pauses every clock. Tap and keyboard use the same target ids; Cancel clears selection and candidate destinations remain visibly distinct.

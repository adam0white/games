## Build and save behavior

`scripts/build-archives.mjs` checks out each fixed source in a temporary worktree, installs its exact lockfile, and builds its original TypeScript/Vite game. Only compiled assets are copied. Each gets the appropriate Vite base path, a build-only storage adapter and an archive-local notice link. The original Git commit stays unchanged. `archive.json` discloses source, adaptations, Node version and builder hash. It does not describe the archive as a bit-identical original deployment.

Each archive's storage uses its own prefix. Existing root saves and the other archive's saves are not loaded or overwritten. Historical progress is not automatically copied; import a compatible exported save inside its matching version. Storage isolation is convenience isolation, not an origin-level security boundary. The adapter covers the actual getItem/setItem/removeItem calls in these two fixed sources, not every possible browser Storage API.

`npm run build:archives` appends archives to a built primary `dist`. `npm run deploy` runs the complete main check/build, then archive builds, then Wrangler dry run/deploy. Building the main site alone clears generated archives; deploy deliberately regenerates them. Public verification checks the root release and both archive manifests/pages. Third-party notices remain with each archive. Private research and source trees are not copied.

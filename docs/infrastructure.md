# Registry and release

`games.json` contains `hfVersion` and `games`, initially empty. Each entry has a lowercase path-safe `slug`, `source` with original GitHub `repository` URL and full `commit` SHA, and a nonempty `saveSchema`. Import source without squashing; its source commit must remain an ancestor. Compare the imported subtree against the source tree during import. Each package at `games/<slug>` pins the registry HF version exactly and supplies `check:lane`, `test`, and `build` scripts. Keep the workspace lockfile current. Installed HF aliases and differing versions are forbidden, including transitive versions. Each game must install the lab client.

CI computes affected games from the base diff. Changes outside registered game paths check every game. The aggregate `ci` job runs the same result gate covered by the tooling tests; a full build runs whenever the registry is nonempty. Bootstrap CI permits an empty registry but build and deployment refuse it. All jobs use full history.

A release checks clean source, latest remote main, and successful exact-commit push CI including its `ci` job. It installs and builds from a fresh detached worktree, clears every game output, assembles all games, scopes headers and redirects, and emits `dist/<slug>/release.json` with lineage, engine, lab and save schema. It then deploys through Wrangler and checks each manifest directly at `https://play.adamwhite.work` without redirects. Hosting configuration remains separate. Verify gameplay, telemetry, identity, recording consent, CSP and offline behavior independently; a matching manifest alone does not establish them.

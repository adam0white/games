# Games monorepo

Human Framework remains an external published dependency. Each game lives at `games/<slug>` and is listed in `games.json` with its original repository and full source commit. Preserve imported history without squash, except for the explicit Neighbours signed-import ruling below. Games that use HF pin the registry's exact HF version. HF is optional for new games (owner, 2026-11-13: HF "shouldn't restrict our Game lab"). Each game owns its rules, assets, replay and first-minute tutorial.

Do not overwrite another agent's work; use a separate worktree or branch. Use pnpm with the committed workspace lockfile and the pinned Node version. Run `npm run check:lane` before committing and `node scripts/prepare-game.mjs <slug>` and `node scripts/check-game.mjs <slug>` for each affected game before delivery. Shared configuration and registry changes require all game checks. Sign commits where a signer is set up. Unsigned commits are allowed (owner, 2026-11-25: "unsigned commits are fine"); sign where a signer is already set up, as on the Mac mini, and do not block cloud work on signing. GitHub does not require signatures on main and no check reads them. One PR combines related work per repository. Merge only with exact-head green CI. A hosted Codex review is optional; ask for one when a change touches signing, deployment or shared build scripts.

The full deployment assembles every game. Deploy only the exact clean commit with successful main CI; verify each live `release.json`. For asset verification use the exact successful Deploy run’s `games-static-<commit>` artifact, verify its digest, receipt commit and file hashes; local rebuild bytes may differ. Keep each game's service worker, storage, CSP, recording notice and lab behavior isolated under its game path. Do not move HF engine code into this repository. Original repositories are retained; ask the owner before archiving one.


Archived code lives under `archive/` and is not built, served or checked; `archive/README.md` lists what is there, why, and how to bring it back. Do not port, polish or upgrade archived code.

Before you write input, sound, pause, menu, save, shop or feedback-button code in a game, use or extend the kit.

A new experiment that records play adds its slug to `LAB_PROTOTYPES` in human-framework `apps/site/src/lab/games.ts`. A Worker route under play.adamwhite.work adds its path to `reservedPaths` in `worker-settings.mjs`.
Storage keys and formats never change.
Reuse before you build. When two games need the same thing, move it to the kit in the same change.
Owner, 2026-11-23, revised 2026-11-28: the strongest sessions plan, review and decide, and may also build. Handing gameplay building, polish and ports to subagents or other models' agents is still fine; model strength matters, so give the hard core of a game (its first contested situation, its sim, a rebuild) to the strongest model available and say which model built what.

## Worker observability (owner direction, 2026-11-24)

Every Worker that runs code has logs, traces and Cloudflare Issues on. Start a new Worker from `workers/observability/template.wrangler.jsonc`; `scripts/observability.test.mjs` fails `npm test` when the block is missing. Report a handled failure with `console.error(error)`. Never log note text, tokens, tester ids or player ids. Cloudflare starts a Claude routine for each new issue; its record is a GitHub issue labelled `worker-issue`. The rule, what is stored and the routine are in `workers/OBSERVABILITY.md`. There are no exceptions (owner decision, 2026-11-24). Turning logs, traces or Issues off for a Worker is an owner decision.

Proposals from the direction document (owner approved the document on 2026-11-14 and may change any detail):

- **Bake-off.** Build a few small entries in about two weeks; the owner plays each for ten minutes and picks one. The winner gets the remaining effort toward a game outsiders finish without help and recommend.
- **Experiment lane.** An experiment needs green CI only. It does not need HF, a replaying export, a cast registry entry, a design document or a hosted review until it graduates. An experiment is a static directory `experiments/<slug>/` with an `index.html`; the build copies it to `/<slug>/` (see Experiments above). It has no `games.json` entry, so the HF pin and release-manifest checks do not apply. An experiment that graduates moves to `games/<slug>` and meets the game rules.
- **Taste gates.** Concept card, then two to four look variants, then a ten-minute play verdict, then outsider-ready. Each gate is one short ask to the owner.
- **Spend.** Paid art, music or other assets are allowed only under a cap the owner has set, and each purchase is logged in the repository. The cap is $1 a month in total for now (owner, 2026-11-25). Log each purchase in `docs/spend-log.md` before or with the change that uses it. A purchase that would pass the cap needs an owner decision first. No domain is being bought for Crumbwar.

## Neighbours history exception — coordinator ruling, 2026-11-11

Concordia contains unsigned upstream commits. Its Neighbours subtree split also produced unsigned commits. Keep the public, archived `adam0white/concordia` available as the exact full-history source (owner ruling, 2026-11-12). Neighbours therefore uses one signed import, recorded in `games.json` as `source.history`, while `source.repository` and `source.commit` retain the original provenance. The build and game checks require that import commit to be an ancestor and its imported game tree to match the pinned tree object. All other original source commits must remain ancestors of main. Do not expand this exception without an explicit coordinator or owner ruling. Do not re-sign original history. See `docs/migration-lineage.md` for exact retrieval commands.

CI speed (owner, 2026-11-23): main no longer requires a pull request to be up to date. A pull request that changes shared code (`scripts/`, `src/`, workflows) does not check every game; that run happens on main after the merge and every night at 09:17 UTC, and can be started by hand (`gh workflow run CI`). A pull request that changes one game still runs that game's checks. If the nightly run fails, fix main before the next shared change.

**Options as settings (owner, 2026-11-27).** "Almost always, give the players more options. The art styles is a good example of this. Give this as a setting, set a default, then check how many players changed it and to what." When a choice could go more than one way (a look, a difficulty, a control scheme, a pace), ship it as a setting through `experiments/kit/settings.js`, pick the default, spread `snapshot()` into `rec.start`, and read the `setting` events and run snapshots in the lab records before changing the default.

**Playable first (2026-11-27).** When a game works but is thin, or a new direction starts, follow `docs/playable-first.md`: get the target in the owner's words from a playable build, build one complete contested situation first, measure every choice against doing neither, run a cold first-play check alongside the build (it does not block new features; owner, 2026-11-28), and say what no person has played. It holds the review prompts and a launch prompt.

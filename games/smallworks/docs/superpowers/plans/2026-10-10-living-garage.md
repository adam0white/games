# A living garage iteration

Goal: deepen the accepted curious opening into a richer family-and-garage chapter, with noticeable changes, distinctive objects, optional backstory and causal human consequences.

Owner direction: continue autonomously, delegate almost all implementation, let workers bring taste and nuance, and polish through lightly briefed game testers and a wildcard before requesting another playtest. This replaces the prior stop-at-first-opening condition.

## Scope and ownership

- Engine worker: timed verification that can run while drinking tea or doing another repair; early handback and understandable consequences; distinct torch method; optional story integration; existing HF relationships/capacity affect at least one observed response. Own engine, types, humans module and behavioral tests.
- Story worker: restrained unfolding family backstory, optional conversations, distinctive voices/object histories and a plausible first observing-friend beat. Own story module and verbatim owner playtest record.
- Interface worker: distinct local object appearances, light action-intent cues, changed-evidence feedback, dialogue fade and brief reveal timing near the choices, reduced-motion support. Own presentation/storage files and UI tests.
- Controller: coordinates interfaces, vets taste and causality, records decisions, verifies integrated build, delegates lightly briefed and wildcard reviews, fixes verified findings through the workers and integrates locally.

Public GameView is the UI boundary. Optional ActionView.intent, ObjectView.appearance and GameView.humanNote/moment can extend it. Hidden faults and true numerical human state stay out of the interface.

## Acceptance and stopping condition

A coherent chapter includes optional story routes, useful parallel repair/waiting, a different torch interaction and a real HF-driven human response. Matched controls distinguish social interaction from equal elapsed time. Save/export/replay preserve actual current-engine state; previous engine-2 progress has a verified migration path. Existing tests, new behavioral controls, browser play and reviews pass before delivery.

This is progress toward apprenticeship, not independent apprentice acceptance. The future teaching/transfer controls remain mandatory. No new HF faculty or release is assumed. No servers, business dashboard, public publishing or multiplayer.

## Review focus

- Players watching buttons should notice the consequence without hunting above.
- Tea and optional conversation should have natural availability and reactions, without endless identical reward farming.
- Verification cannot be completed instantly merely by calling it a long check.
- Shelved work and callbacks must remain recoverable; room/time limits have visible fictional reasons.
- Legacy migration, async transition timing, reduced motion and imports must not lose progress or create double actions.

## Deferred taste notes

Moving the selected option into the status area, more elaborate item transformations and larger scene choreography are retained for later animation work. The current pass uses a modest fade and local consequence cue. Broader diagnosis/knowledge revision must reflect real acquired evidence, not decoration pretending an underlying belief model exists.
